Using the color palette consistently creates a cohesive and recognizable visual identity
across all Sicoco products and interfaces. This approach is built on a clear set of
guidelines for applying the Sicoco component library across both light and dark themes.

---

## Color anatomy

Sicoco's color system is organized into **semantic color families** and a **neutral palette**.
Each family expresses a specific role or intent in the UI:

- **Primary** — The main brand color (indigo). Used for primary actions, links, focus rings, and interactive highlights.
- **Secondary** — A supporting cyan/teal tone. Used for complementary UI elements and accents.
- **Neutral** — Grayscale with a subtle blue-gray cast. Drives backgrounds, borders, text, and surface layering.
- **Semantic colors** — Communicate system feedback and status:
  - **Success** — Confirms a positive outcome (green).
  - **Warning** — Signals caution or a non-blocking issue (amber).
  - **Danger** — Indicates a destructive or error state (red).
  - **Info** — Provides informational context; shares the same palette as Primary.
- **Orange** — A supplemental accent for badges, highlights, and decorative elements.

### Scale model

Every color family uses a **10–100 scale** where lower numbers are lighter tints and higher
numbers are darker shades. The step with the highest chromatic intensity (the "pure" hue)
sits at **100** in light mode. This scale maps directly to Tailwind utility classes:

```
bg-primary-10   → lightest primary tint
bg-primary-100  → full primary hue
```

## Implementing color

Sicoco uses **CSS custom properties** and **Tailwind utility classes** together to apply color.

### CSS custom properties (tokens)

Each color step is a CSS variable holding space-separated RGB channel values:

```css
--color-primary-100: 39 55 201;
```

Consume them in custom CSS via the Tailwind `rgba()` helper pattern:

```css
.my-element {
  background-color: rgba(var(--color-primary-100) / 0.15);
  color: rgba(var(--color-primary-100) / 1);
}
```

### Tailwind utility classes

The Tailwind preset bundled with `@sutekitechid/sicoco-v3-next` maps every CSS variable
to a utility class automatically:

| Class example | What it does |
|---|---|
| <CopyClassName className="bg-primary-100" /> | Sets background to the full primary hue |
| <CopyClassName className="text-neutral-80" /> | Sets text to neutral-80 |
| <CopyClassName className="border-danger-40" /> | Sets border to danger-40 |
| <CopyClassName className="ring-success-60" /> | Sets ring to success-60 |

Opacity modifiers work out of the box because the variables use RGB channels:

```html
<div class="bg-primary-100/10">…</div>
```

## Themes

Sicoco ships with two built-in themes: **Light** (default) and **Dark**.
Themes are activated by toggling the `data-mode="dark"` attribute on the root element.
Each theme maps a different set of hex values to the same CSS variable names, so
components automatically adapt without any class changes.

```html
<!-- Light theme (default) -->
<html>…</html>

<!-- Dark theme -->
<html data-mode="dark">…</html>
```

### Light theme

The light theme uses white and very light neutral tints as page backgrounds.
Color families have their full-intensity hue at step **100** and feather out to
near-white at step **10**.

### Dark theme

The dark theme is applied with `data-mode="dark"`. In dark mode the semantic color families
**shift their base hue** so it reads against a dark surface: step **10** becomes
the most saturated value and higher steps fade toward the background. Neutral colors
invert so that neutral-60 through neutral-100 all resolve to an off-white value,
keeping text legible on dark surfaces.

## Interaction states

Sicoco components handle interaction states through Tailwind's state variants.
The following guidelines describe how each state should be expressed using
the color scale.

### Hover

Hover states use a **one step darker** value from the element's base color.
For most components this is handled internally, but when building custom elements
apply `hover:` variants with the adjacent darker step:

```html
<!-- Button-like element: base primary-100, hover goes darker via opacity -->
<button class="bg-primary-100 hover:bg-primary-100/80 text-white">
  Click me
</button>
```

For backgrounds sitting on light layers, a subtle neutral tint is appropriate:

```html
<li class="hover:bg-neutral-10 px-4 py-2 cursor-pointer">List item</li>
```

### Active / Pressed

Active (mouse-down) states step **two levels darker** than the base color, or use an
opacity reduction. Apply via Tailwind's `active:` variant:

```html
<button class="bg-primary-100 active:bg-primary-100/60 text-white">
  Press me
</button>
```

### Selected

Selected states — used in navigation, tabs, and list selections — use a one step
darker background with the matching text color:

```html
<li class="bg-primary-10 text-primary-100 font-semibold">Selected item</li>
```

### Focus

Focus states use a **2px ring** in `primary-100` for light mode and an appropriate
contrasting ring in dark mode. All interactive components in Sicoco include default
focus ring handling. When building custom components, use:

```html
<button class="focus-visible:ring-2 focus-visible:ring-primary-100 focus-visible:outline-none">
  Accessible button
</button>
```

### Disabled

Disabled elements are de-emphasized using neutral tones regardless of the component's
base color. Disabled states do not need to meet WCAG contrast requirements — they
are intentionally subdued to communicate non-interactivity:

```html
<button class="bg-neutral-30 text-neutral-50 cursor-not-allowed" disabled>
  Disabled
</button>
```

## Accessibility

Color contrast is the most critical accessibility consideration in the Sicoco palette.
All text and interactive elements must meet [WCAG 2.1](https://www.w3.org/TR/WCAG21/) contrast requirements:

| Text size | Minimum contrast ratio | Recommended Sicoco token pairs |
|---|---|---|
| Small (< 24px) | **4.5 : 1** | `neutral-100` on `white`, `primary-100` on `white` |
| Large (≥ 24px or bold ≥ 18.67px) | **3 : 1** | `neutral-80` on `neutral-10`, `primary-90` on `white` |
| Graphical / UI elements | **3 : 1** | `success-100` on `white`, `danger-100` on `white` |

### Safe combinations (light theme)

- `text-neutral-100` on white or `bg-neutral-10` — exceeds 4.5:1
- `text-primary-100` on white — exceeds 4.5:1
- `text-white` on `bg-primary-100` — exceeds 4.5:1
- `text-white` on `bg-danger-100` — exceeds 4.5:1
- `text-white` on `bg-success-100` — verify; success-100 is a mid-green, test with a contrast checker

### Avoid

- Do not place `warning-100` (#FFA800) text on white — fails 4.5:1 for normal text.
  Use `warning-100` for decorative backgrounds or icons only, paired with dark text.
- Do not use `neutral-40` or lighter for body text on white backgrounds.
- Do not rely on color alone to convey state — always pair color with an icon, label, or pattern.
